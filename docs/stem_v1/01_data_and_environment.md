## 导入时必须处理的差异

1. `concept.json` 和 `problem.json` 实际为逐行 JSON；`concept2id.json` 实际为带引号的逗号分隔行。`id2concept.json` 在力学中是 CSV，在逻辑学和 PHP 中是 JSON；不能只按扩展名选解析器。
2. `problem.json.detail` 为 Python 字典字符串。采用 `ast.literal_eval` 或受限数据解析，禁止 `eval`；其中保留选项、标准答案、题型和原始课程 ID。
3. `problem_info.json` 不包含完整选项和答案，不能单独用它作为可作答题库。
4. 三份题库中所有 `problem_info.difficulty` 值均与对应 `cognitive_dimension` 相同。先保存为原始认知维度；教学难度、课程层级、认知题型另设字段，未知时为 null。
5. 跨课程采用 `(source, course_id, source_id)` 唯一标识，防止几份文件中同为 `1` 的知识点和题目发生冲突。
6. 原始题干含 HTML、公式、远程图片或本地图片占位符时，分别提取、清洗和验证；未能恢复的关键图示会阻止题目进入可判分题库。
7. 课程名称可由明确课程 ID 建立映射；现有概念集合不是官方章节目录，模型生成的章节归类标为整理结果。

## 导入范围

允许：课程元信息、概念 ID 与名称、题干、选项、答案、解析、题型、题目概念关系、原始知识路径、必要配图、来源与内容校验值。

不导入：学生身份、原始答题序列、正确率序列、训练测试集、`records.txt`、`student-problem-records.json`、既有学生认知模型与预训练学生权重。

XES3G5M 官方入口提供约 356 MB 的压缩包。此次取得完整的 metadata 子树后停止继续下载交互部分，从已接收的压缩包前缀提取 `metadata/questions.json`、`metadata/kc_routes_map.json` 和 `metadata/images/`，逐文件计算 SHA256 并核对图片引用。未解包交互 CSV 或 embedding 文件；本地临时压缩包是前缀，不是完整归档文件。

参考入口：[XES3G5M 官方仓库](https://github.com/ai4ed/XES3G5M)。下载脚本位于 [download_xes3g5m.py](../../scripts/data/download_xes3g5m.py)，解包统计写入 `data/raw/xes3g5m/manifest.json`，保留文件的 SHA256 写入 `file_checksums.json`。摘要用于本地完整性追踪，并非来自官方签名校验。manifest 明确标记教学元数据子树完整、压缩归档未完整下载。

## 知识结构的边界

CBEGRec 正文说明，MOOCRadar 原始内容缺少概念关系，论文利用历史交互构造转移图并以 LLM 修正。已检查本地 `src/kg/hybrid_kg_construction.py`，其构图入口确实读取 `records_path`；不能将现有 `KG_structure.json` 宣称为人工验证的教材先修图。

第一版的基础关系直接来自教学元数据：

- `CONTAINS`：课程、章节或原始知识路径中的包含关系。
- `ASSESSES`：题目对应知识点。
- `RELATED_TO`：由同题概念共现构造，并注明来源。
- `PREREQUISITE_OF`：有独立依据的教学先修关系，与上述关系分别保存。

数学 `kc_routes` 首先解释为知识分类路径，不能仅因父子层级就将其转换为先修关系。

前三门课程的现有推断 KG 可作为候选关系参考；导入候选边时保留 `legacy_inferred` 来源，不能用于强制解锁。新的先修候选根据知识点、题目内容和教学资料生成，通过 ID、课程范围、自环、环路和方向检查后，仍保留“推断”属性。无环只能证明结构条件，不能证明教学关系正确。

## 从名称到可教学内容

知识点详情使用单独的内容版本，而不直接覆写原始概念：定义、适用条件、核心公式、示例、常见错误、三层级学习要求、关联题目和来源。

优先使用题目已有解析和原始教学文本；缺少内容时，知识点 Agent 基于关联材料生成讲解并保存为 `llm_generated` 内容。生成解析需与原始答案核对，无法确认的冲突题进入待处理队列。未经外部校准，不能把模型生成内容标为专家审核。

所有课程使用同一按需内容构建和缓存机制；四门课程均完成代表性知识点与题型验收，不能仅对力学准备优质演示样本。

## 数据模型

| 实体 | 关键字段与职责 |
|---|---|
| Course | 来源、课程 ID、显示名、范围说明 |
| Concept | 课程 ID、原始 ID、名称、类型、层级和版本 |
| ConceptContent | 内容正文、生成或导入来源、证据引用、校验状态 |
| Question | 题干、选项、题型、答案与解析的服务端引用、来源、可用状态 |
| QuestionConcept | 多知识点覆盖、认知要求、来源及权重 |
| ConceptRelation | 类型、方向、依据、置信说明、推断或验证状态 |
| Resource | 图片与视频链接、来源、关联概念、可用状态 |
| Attempt / Evidence | 当前用户答案、提示情况、判分与证据标识 |
| StudentConceptState | 三层级状态、证据数量、模型诊断版本 |
| Session / TopicSegment | 多目标议程、当前题目、切换和恢复信息 |
| MemoryItem | 学习偏好与错误模式、来源、适用范围、有效状态 |
| AgentRun / ToolCall | 模型、技能版本、工具记录、耗时、Tokens、错误 |

前端题目接口仅返回公开题干和选项，标准答案和判分规则留在后端。题目已出示后冻结题目及答案版本，防止评估时被重新生成。

## 数据验收

导入前后核对数量、重复 ID、悬空知识点、空题干、无法解析的答案和缺失图片。保留原始值与规范化值；坏数据隔离并输出原因。幂等导入重复执行不增加重复记录，版本变化可追溯。

四门课程均抽样检查题干、公式、选项、答案和知识点关联；数学额外检查图片定位和 `kc_routes` 拆分。论文的概念数量按其统计口径比较，目录中的路径节点数和叶知识点数分别统计。

## 环境处理

现有 `.env` 仅作为连接设置来源，读取路径由配置项显式指定。只选取模型和必要数据库参数，生成本项目自己的配置说明与忽略规则。不要把合同项目的库名、业务表或全部环境变量直接沿用。

| 依赖 | 2026-10-19 已核实状态 | 实施动作 |
|---|---|---|
| 文本模型 | deepseek-flash 的一次真实工具调用请求成功，HTTP 200，约 1.17 秒，381 Tokens | 继续验证完整工具往返、结构化输出、异常和超时行为 |
| 向量模型 | text-embedding-v4 实际返回两条 1024 维向量，HTTP 200 | 用于文档与查询向量化，继续验证批量导入与重试 |
| MySQL | 配置目标的 TCP 端口可连接 | 验证登录并使用独立 stem_tutor 库，执行本项目迁移 |
| Neo4j | 安装目录存在，默认 7474/7687 连接超时 | 检查进程与监听，启动后执行只读查询验证账号 |
| Elasticsearch | 已验证 9.3.2、green、Basic 许可，无额外插件 | 第一版必需；建立独立文本及向量索引，支撑 RAG 和快速查题 |
| Redis | 本机端口可连接 | 可选缓存，首版不作为必需业务组件 |

Neo4j 使用 `StemTutor` 标签和 `dataset_namespace` 隔离本项目图数据，维护查询限定该命名空间。社区版部署不假定支持任意数量独立业务数据库。生产数据导入和连接配置进入实施阶段后再验证，当前端口连通不等于数据库登录或完整接口可用。

文本模型测试只发送合成的连通性消息，模型返回了预期的 `lookup_concept` 调用及参数；没有向模型发送项目文档或学生资料。用量与结果保存在 `data/reports/model_probe.json`，单次耗时不代表完整学习流程的延迟。

检索环境记录见 `data/reports/es_environment_probe.json` 与 `data/reports/embedding_probe.json`。检索材料按知识点与段落分块，向量索引、来源、答案可见性和图结构映射统一遵循 [RAG 与 Graph RAG 及题目检索](03_retrieval_and_graph_rag.md)。
