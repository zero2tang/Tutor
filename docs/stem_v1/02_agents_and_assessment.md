## 四个角色及职责

| 角色 | 负责的决定或内容 | 结构化产物 | 约束 |
|---|---|---|---|
| 主 Agent | 理解目标、选单点或多点模式、决定讲解练习补救与复习、汇总结果 | LearningPlan、NextAction | 可处理简短澄清；复杂讲解与题解交给对应角色；不写最终掌握度 |
| 习题 Agent | 检索题、生成题、分步题解、根据错因生成变式 | ExerciseDraft、Solution | 不以自己生成的答案为唯一质量依据，不自行判定学生掌握 |
| 知识点学习 Agent | 分层讲解、例子、公式推导、追问、检索学习记忆与视频 | Lesson、PracticeRequest、MemoryCandidate | 需要练习时返回出题请求，由主 Agent 调度；不绕过评估改状态 |
| 学生状态评估 Agent | 判分、错因与先修归因、三层级诊断、预测与反思 | AssessmentDraft、StateUpdateProposal | 只提交提案，状态由证据服务校验并提交 |

四个业务角色分别拥有 AgentDefinition、技能和工具权限，但不对应四个独立常驻进程。每次运行保留角色、输入上下文、工具调用、输出版本和预算。习题校验与评估内部可以多次调用模型，属于角色内部步骤，不额外扩展顶层角色。

四个角色及共享执行器均在 Python 后端运行，由 FastAPI 接收学习请求并推送执行事件。技能加载、模型调用、工具权限、结果校验和状态提交统一在后端完成；网页呈现学习内容、题目和反馈，并收集学生输入。

用户只面对一个学习界面。主 Agent 统一组织响应，但可以将专业角色的结果直接流式呈现，避免把一段讲解反复转述。

## Skill 的划分

Skill 定义何时使用、需要哪些输入、教学步骤、允许工具、结构化输出和停止条件，采用可版本化文件，避免只更换一段角色描述。

| 角色 | 技能 | 核心行为 |
|---|---|---|
| 主 Agent | single_concept | 聚焦一个知识点，发现先修缺口后补充并返回 |
| 主 Agent | multi_concept | 拆目标、选先修与相关概念、安排顺序、跨知识点综合练习 |
| 习题 Agent | recall | 定义、条件、公式或基础事实的回忆 |
| 习题 Agent | understanding | 解释原因、辨析反例、比较关系 |
| 习题 Agent | application | 计算、推导、代码分析和情境迁移 |
| 知识点 Agent | foundational | 直觉、定义、符号解释和最小例子 |
| 知识点 Agent | intermediate | 推导、适用条件、边界和典型变式 |
| 知识点 Agent | advanced | 多概念结合、复杂问题、迁移和错误辨析 |
| 评估 Agent | initial_diagnosis、incremental_diagnosis | 冷启动证据汇总、已有状态的局部修正 |

知识点内容类型另外保存为事实、概念、过程、建模等属性，用来选择教学活动。知识点学习层级、题目认知类型与题目难度是三个独立维度；例如应用题可以很简单，理解题也可以很难。

初始阶段每项技能带结构化输出校验器，异常输出可以有限重试。运行日志记录实际调用了哪个技能及其版本，便于验证并非四个提示词模拟完成。

\[
\mathrm{allow}=\mathrm{role}\land\mathrm{course\_scope}\land\mathrm{session\_state}\land\mathrm{budget}.

视频检索工具需要后端自己的可配置检索适配器和缓存；开发期间使用的 Codex 检索工具与账户权限不会自动成为部署后系统能力。查询无结果或提供方不可用时如实返回状态，不编造链接。

## 评估论文与实现映射

参考 LEARNERCOMPASS 第 3.2 节、附录 A.2、图 6。论文正文描述 Encoder 中的 Assessment 与 Summary，以及 Decoder 中的 Predict 与 Tracing；第一版将其作为学生状态评估 Agent 内部的四个阶段。

| 论文设计 | 第一版实现 |
|---|---|
| Assessment | 根据原题、标准答案、真实解题过程和知识结构，区分概念错误、先修缺口与计算失误 |
| Summary | 汇总证据，形成当前知识点各学习层级的粗粒度状态 |
| Predict | 使用冻结的题目和作答前状态，预测本题表现；不读取当前用户答案 |
| Tracing | 比较预先预测与真实表现，说明差异，提出有证据支持的局部状态修正 |

预测与诊断的数学含义是：寻找能够更好解释实际作答的学生状态，而不是把回答得分直接改名为掌握度。

\[
\hat r_t=\operatorname{Predict}(q_t,\theta_t,H_{<t}),
\qquad e_t=r_t-\hat r_t.
\]

这里 \(q_t\) 为题目，\(\theta_t\) 为作答前状态，\(r_t\) 为真实判分。论文正文讨论响应概率，附录 Predict 提示词输出 0 或 1；第一版保留二值预测和解释性诊断，不将其表述为已校准概率。

对于知识点 \(c\)，按照论文附录保留三个层级：

\[
\theta_c=(\theta_{c,\mathrm{beginner}},\theta_{c,\mathrm{advanced}},\theta_{c,\mathrm{proficient}}).
\]

界面对应“基础、进阶、熟练”，用于说明在该知识点上能完成何种任务。每个层级还有 `observed`、`evidence_count`、`confidence_label` 和 `last_evidence_at`；没有证据时为空并显示“待评估”。基础会了不代表进阶或迁移已经得到验证。

Encoder 的五级映射依论文采用 \(\{0,0.25,0.5,0.75,1\}\)。这些是粗粒度诊断等级，不应显示为精确成功率。

Decoder 采用有界局部更新，以下为本项目增加的工程约束，不是论文已经验证的固定算法：

\[
\theta'_{c,l}=\operatorname{clip}_{[0,1]}
\left(\theta_{c,l}+\operatorname{clip}_{[-\delta_{\max},\delta_{\max}]}(\Delta_{c,l})\right).
\]

LLM 提出 \(\Delta_{c,l}\) 及关联证据；服务检查涉及的知识点和层级、证据 ID、评分可信度、是否看过提示或答案及本次更新幅度。首次有证据时使用 Encoder 初始化；已有状态再使用局部更新。限幅值与掌握判定门槛属于可配置策略，需用实际题目验证后确定。

同一题上循环修正到“预测一致”不足以证明学生模型准确，多种状态可能解释同一个对错结果。因此第一版默认每次真实作答只做一次反思，至多一次针对结构化输出的修复；同一证据不会因内部重试重复计入。下一道独立题继续检验修正结果。

## 首次学习与持续诊断

1. 新用户可以填写学习目标与自述基础，保存为自述信息，不作为已掌握证据。
2. 根据目标选择少量现有诊断题，覆盖当前层级与关键先修；覆盖不足时保持未测状态。
3. 作答前冻结题目、参考答案、状态版本和预测；无法取得预测时仍可作答，记录本题没有预测数据。
4. 客观题优先确定性判分；数值、单位和公式题采用明确的等价规则，主观解释采用固定 rubric 和模型评估。
5. 低置信、答案歧义、图像不可读或参考答案冲突时使用 `ungraded`，请求补充或更换题目，不强行写入对错。
6. 评估器读取真实证据，生成当前点诊断；先修点缺口标为待验证假设，只有明确证据支持时才更新相关状态。
7. 证据与状态在同一业务事务中提交；主 Agent 读取新版本决定下一步。

被提示过或看过答案的作答保存为 assisted，不能与独立作答等量作为掌握证据。同题多次作答保留过程，但掌握门槛要求独立题目和目标层级覆盖，避免重复刷一题导致虚假掌握。

论文涉及的多模型 AB-MCTS 路径搜索不属于此次“参考评估设计”的必需复现范围。第一版多知识点规划使用图约束候选路径和主 Agent 决策，并明确它是本项目实现。

## 题目生成与可信度

优先检索真实题目，保持原始题干、答案、来源和知识点绑定。需要新题时，习题 Agent 内部执行生成、独立解答、规则与目标覆盖检查；独立解答不读取生成阶段给出的参考答案。

这些步骤可以借鉴 CBEGRec 的 Teacher–Solver–Critic 思路，但都位于习题角色内部。达到重试预算仍不一致的题不出示给学生，改用现有题或说明当前无法生成合格题。同一模型进行交叉解答并不等于外部正确性证明。

数学与力学重点检查条件、量纲、符号和答案可解性；逻辑学检查论证结构和反例；PHP 检查语法版本及代码语义。第一版不执行任意用户或模型生成的 PHP 代码；确需执行时另行设计受限运行环境。

## 会话与长期记忆

区分会话、连续知识点片段与跨会话知识点工作区。一条会话可以“学 A—补 B—返回 A”；每次切换保存原题、当前阶段、已讲内容和返回位置。

证据账本保存不可变事实，学生状态是其可重建投影，学习记忆保存带来源的偏好与错误模式，会话摘要用于上下文压缩。摘要不能覆盖原答案、未完成题目和状态版本。

MemoryService 接收候选记忆并维护有效、暂定和失效状态。用户可以查看、纠正或删除偏好记忆；学习诊断保留版本及来源。复习由服务记录到期任务，主 Agent 在学习时提示，不依赖持续运行的模型后台进程。

## 执行、失败与观测

- 每轮固定最大工具次数和模型预算；只对瞬时错误有限重试，用户可取消。
- 模型返回的最终结构必须通过契约校验；工具异常、生成失败、未完成评估不会被包装成成功。
- SSE 事件带 session_id、turn_id、event_id；后端先保存关键事件，再推送前端。
- 答案提交带幂等键；状态提交检查版本，防止重复计分和旧结果覆盖新状态。
- 持久保存 awaiting_answer、assessing、completed 或 failed 等阶段；重启恢复根据数据库事实执行。
- 展示可核实的工具调用、状态变化和简短判断依据；不以模型内部思维内容作为审计记录。
