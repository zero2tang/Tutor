# 主 Agent 的题目上下文

本次修复出题后主 Agent 只看到提示文字、题干留在消息元数据中的缺口。题目作为会话业务对象读取，不依赖最近十条正文是否包含完整题干。

## 输入与查询

普通规划、知识讲解和答后下一步决策新增 `exercise_context`：

- `active_exercise`：当前讨论题的完整公开冻结题干、选项、配图引用、版本、相关知识点、交互状态及本人作答摘要。
- `pending_exercise`：讨论历史题时若另有未完成题，单独提供其快照，避免历史追问覆盖待答状态。
- `recent_exercises`：最近三条出题记录摘要，含总数与分页信息。

主 Agent 可调用两个只读工具，课程、学生和会话身份由服务端注入，不接受模型覆盖：

1. `list_session_exercises(query?, limit?, offset?)`：按时间倒序分页定位历史题，最多十条。
2. `get_session_exercise(exercise_id?)`：读取指定出题记录的公开快照；省略 ID 时取当前讨论题。

`exercise_id` 是出题消息的 ID，不是题库题号。同一道题重复出现时，作答按本次出题至下一次出题之间的时间范围关联。

## 题解与版本

`Plan.exercise_id` 可指定历史讨论对象。规划器校验它属于当前会话；题解流程使用该记录对应的契约，并接收用户的具体追问。讨论历史题不会替换另一道待答题，题解工具范围也按所选题目重建。

新出题记录在消息元数据的 `_exercise_contract` 字段保存内部冻结契约。消息公开序列化统一移除下划线私有字段，主 Agent 上下文与查询工具再按公开字段白名单投影，不包含标准答案、私有解析或原始验证元数据。HTTP 恢复和 SSE 消息使用同一公开序列化路径。

已有记录不做回填。旧题优先取仍保留的冻结契约；若没有内部快照，仅在题号、版本、题干、选项等与现行题库一致时才允许引用现行答案，否则保留历史公开题目并拒绝混用新答案。旧记录无法追溯未记录的答案修改；新记录使用内部冻结快照。

网页恢复与出题显示同样使用冻结公开题干。配图只传资源引用，当前文本模型仍不具备读图能力。
