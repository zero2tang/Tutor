# 同轮工具并发执行

一个 Agent 在一次模型响应中返回多个 `tool_calls` 时，运行时会并发执行，默认最多四个。多个 Agent 的并行出题能力继续保留；两种并发分别控制，不改变同一会话只能有一个外部业务操作的约束。

## 执行过程

1. 模型决定需要哪些工具以及各自参数。提示词说明互不依赖、参数已确定的查询可以同轮提出；需要前置查询结果的调用应放在下一轮。
2. 按模型请求顺序预留本轮剩余工具预算，再启动任务。超过预算的调用仍收到对应错误回执，但不会执行，完成先后不影响获准调用的集合。
3. `TaskGroup` 管理任务生命周期，`Semaphore(4)` 限制每次 Agent 运行中同时执行的工具数量。`AgentRunner.run(max_tool_concurrency=...)` 可由服务端调整，取值 1–16，模型和浏览器不能覆盖该参数。
4. 每个调用都检查角色白名单和参数，并使用独立复制的 `ToolContext`。同步课程、学生、难度和技能读取在线程中执行，SQLAlchemy Session 在所属线程内创建和关闭。异步 ES/Graph RAG 等检索仍在原事件循环中运行，不把 HTTP 客户端搬到其他线程。
5. 工具完成即记录轨迹、引用并发送 `tool_completed`，其中增加 `tool_call_id` 和本轮 `call_index`。完成事件和审计轨迹按实际完成顺序记录。
6. 所有调用结束后，按模型请求顺序追加对应的工具结果；各结果保留原 `tool_call_id`。随后才补入去重后的公开题目图片，再启动下一轮模型推理。

例如，同轮读取学生状态、课程结构和检索教学资料可以重叠执行。搜索后才知道知识点 ID 的详情查询仍需分轮，运行时不会自行猜测依赖或补造参数。模型如果每轮只返回一个调用，也仍按单工具流程执行。

## 错误、取消与缓存

- 参数、权限和单个工具运行错误被转换为该调用的错误结果，不取消其他正常查询，模型可据此调整。
- 不接受缺失或重复的工具调用 ID，避免回执错配；拒绝时不会启动本轮工具。
- 同轮重复读取相同技能使用按技能加锁的复用机制；只回填一份正文，其余返回已加载提示。首次读取失败不会污染缓存，后续调用可以重新尝试；缓存命中仍执行角色和参数校验。
- 取消 Agent 时取消并等待子协程，保留已经完成的轨迹和引用。Python 无法强制终止工作线程，因此同步只读查询会等待完成并关闭连接后再向上传播取消；这段清理受数据库驱动的超时行为影响，不承诺严格的瞬时终止。
- 当前注册工具都是只读查询，写入学生证据、修改待答状态仍由业务服务执行。未来加入有副作用的工具时，需要单独定义是否允许并发及冲突处理。

当前限制是每个 Agent 运行的并发上限，不是全系统所有工具合计最多四个。模型 HTTP 客户端原有三个并发请求的限流继续独立生效。

## 主要文件

| 文件 | 作用 |
| --- | --- |
| `backend/app/agent/runtime/tool_batch.py` | 并发调度、预算分配、错误隔离和技能复用 |
| `backend/app/agent/runtime/loop.py` | 汇总轨迹、按请求顺序回填结果与公开图片 |
| `backend/app/application/agent/registry.py` | 每次权限校验以及同步/异步工具分发 |
| `backend/app/shared/concurrency.py` | 同步只读任务的线程执行及取消清理 |
| `backend/tests/test_tool_concurrency.py` | 通过事件屏障和真实隔离数据库验证执行重叠 |

测试使用临时文件 SQLite，让各工具线程拥有独立连接，避免把默认内存 SQLite 的线程绑定问题误认为业务故障。真实模型评估脚本 `check_agent_autonomy.py` 也改为使用自动清理的临时数据库，不修改历史评估报告。

验证覆盖实际并发、并发上限、独立上下文、乱序回执、工具失败、预算、技能重复与失败重试、权限拒绝、同步数据库线程、异步客户端线程、取消清理及非法调用 ID。没有用未测量的端到端延迟宣称性能提升，也没有发送真实学生内容给外部模型。
