# 生成题的第三次模型语义复核

生成流程由“生成 → 独立求解 → 程序比较答案字符串”改为：

```text
第1次调用：生成题目、参考答案与解析
    ↓
第2次调用：只看题干和选项，独立求解；不接收生成者答案与解析
    ↓
第3次调用：读取原题和两份解答，判断数学语义并整合
    ├─ 等价或正确互补 → 使用第三次调用的统一答案、解析入库
    └─ 实质冲突、题目无效或无法确认 → 重新生成一次
```

第三次调用仍属于现有习题 Agent 的独立运行，使用新增 `exercise/reconcile` 技能，不增加第五个业务 Agent。每次运行有独立消息和 run_id；多题仍按原有并发上限生成。

## 判定契约

`SolutionReview` 返回：

| 字段 | 含义 |
| --- | --- |
| `verdict` | `equivalent` 等价、`complementary` 互补、`conflict` 冲突、`invalid` 题目无效、`uncertain` 无法确认 |
| `answer` | 可接受时给出统一的最终答案，拒绝时为空列表 |
| `explanation` | 综合后的解题解析 |
| `reason` | 通过或拒绝的具体理由 |

等价包括分数与小数、单位换算、数学表达式等价、选项文字与标签指向同一答案。
互补可以是正确解法和说明互补，也可以是两份明确的部分回答分别正确，结合后完整回答原题。例如整数分配部分和余下分数部分可以合成为完整结果。两个错误的最终结论不能被解释成互补，单选不同标签或完整多选答案集合不同也不能简单取并集。

复核只能输出统一答案与解析，不能修改题干、选项、题型或知识点。独立求解的 `valid` 是待核查意见，由第三次调用结合题意复核，不再由程序直接据此否决。

## 程序仍负责的边界

- 校验题型、知识点范围、四个有效选项以及答案格式。
- 单选输出一个有效大写标签，多选输出多个不重复的有效标签，单空填空输出一个统一答案。
- 校验复核 JSON 和接受/拒绝字段之间的一致性，反馈契约错误让当前调用修正。
- 根据模型的 `verdict` 决定接受或重试，不再比较生成答案和独立求解答案的规范化字符串。`normalize()` 只用于选项格式去重等结构检查，不承担数学等价判断。
- 即使前两份答案字面相同，也执行第三次复核，不绕过该步骤。

每道题最多两次生成尝试，即一次初始生成加一次重试。重试输入包含上一份题目、两份答案与解析，以及语义复核的具体理由。网络重试或单次 Agent 的 JSON 修复仍沿用运行时预算，不等同于增加生成尝试次数。

冲突时即使第三次调用认为可以判断哪方正确，也按请求重新生成，不直接选一方继续。两次均未通过时仍按开发阶段现有错误通道上报；不修改学生作答的判分规则。

## 私有诊断与公开边界

新增 `exercise_generation_attempts` 表在复核返回后保存本次尝试的题目草稿、独立解答、语义复核输出、阶段 run_id、任务序号、尝试次数及通过/拒绝状态。格式不合格的草稿也记录拒绝原因。中途网络失败或取消仍通过 AgentRun 记录，不保证保留尚未完成复核的草稿。模型调用完成与题目质量通过分别记录，避免把 `AgentRun.completed` 误认为题目已通过。

该表没有学生端查询接口。公开问题、正常进度消息和 ES 索引不附带其内部答案。新增 `exercise_quality_checked` 事件只包含阶段、状态、判定类别、任务序号及诊断引用，不发送完整答案、解析或可能包含答案的复核理由。按当前开发阶段要求，最终失败仍可通过错误通道显示具体拒题原因，其中可能涉及被拒草稿的信息；不将被拒草稿展示为可作答题。

接受后 `Question.answer` 和 `Question.explanation` 使用第三次调用的结果；`Question.validation` 保存质量方法 `semantic_reconciliation_v1`、判定、三个 run_id 和诊断记录 ID。新题不再标记旧的 `independent_solution_agreed=True`，历史题记录保持原状。

复核依赖模型判断，不构成数学形式化证明。每次生成尝试多出一次模型运行，实际耗时和成本需在业务数据上继续观察。

## 代码与验证

- `domains/learning/schemas.py`：`SolutionReview`。
- `domains/practice/reviews.py`：结构校验、语义复核与诊断记录组装。
- `domains/practice/service.py`：三阶段调用、一次重试、统一答案入库。
- `agent/skills/exercise/reconcile.md`：等价、互补、冲突及不可判定的处理规则。
- `domains/practice/models.py`：私有诊断模型。
- `tests/test_exercise_reviews.py`：格式等价、数学等价的决策接入、互补整合、实质冲突、重试预算、隐私及结构边界测试。

真实模型验收脚本：

```powershell
.\backend\.venv\Scripts\python.exe scripts\evaluation\check_exercise_review.py
```

只发送四个公开自拟样例及解答，使用临时 SQLite，不读写真实学生记录。2026-10-19 验证四项通过：分数/小数等价、面积单位换算、计算冲突拒绝、正确部分结论互补。报告见 `data/reports/exercise_review_live.json`，有限样例不代表通用数学正确率。

完整隔离测试共130项通过，其中新增语义复核专项14项。后端启动时自动创建诊断表；新逻辑需重启后端加载。
